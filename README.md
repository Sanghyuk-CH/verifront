# verifront

프론트엔드 결과물이 맞는지 숫자로 판정하는 CLI.

v0.1은 CSS의 색상 값이 디자인 토큰을 지켰는지 검사한다. `#3b82f5`와 `#3b82f6`처럼 육안으로 구분되지 않는 차이를 잡는 것이 목적이다.

## 판정

| 판정            | 뜻                                             |
| --------------- | ---------------------------------------------- |
| `ok`            | 토큰과 값이 일치                               |
| `near`          | ΔE00 1.0 미만. 육안으로 구분되지 않는 다른 값  |
| `violation`     | ΔE00 1.0 이상                                  |
| `alpha-variant` | 색은 토큰과 같고 알파만 다름                   |
| `unknown-token` | 어디에도 선언되지 않은 변수 참조               |
| `uncomputable`  | `color-mix()` 등 정적으로 값을 알 수 없는 자리 |

`uncomputable`은 위반이 아니다. 검사하지 못한 자리라는 표시다. 통과와 구분되어야 한다.

거리는 RGB 유클리드가 아니라 ΔE00으로 잰다. RGB 공간은 지각 균등하지 않아 같은 거리가 색 영역마다 다른 뜻이 된다. `#ffffff`에서 RGB 거리 13.9는 ΔE 1.60이고 `#6b7280`에서 12.8은 ΔE 3.29다.

## 검사하는 것과 하지 않는 것

`var()` 참조는 값을 따라간다. 문서 안에 선언이 있으면 이름이 토큰과 같아도 그 값으로 판정한다. 이름만 대조하면 토큰 이름에 다른 값을 넣은 경우를 놓친다.

명명색은 값이 토큰과 같으면 통과한다. 토큰 참조를 강제하는 것은 stylelint의 관심사고, 이 도구는 결과 값이 디자인 시스템 안에 있는지를 잰다.

`box-shadow`, `text-shadow`, `background-image`는 기본 검사 대상에서 제외한다. 그림자와 그라디언트의 색은 토큰에 없는 것이 정상인 경우가 많아 오탐이 신호를 덮는다.

SCSS는 컴파일한 뒤에 검사한다. `darken($primary, 10%)` 같은 함수는 소스에 값이 없다.

## 실험

`experiments/`에 AI 생성물의 토큰 준수율을 측정한 실험이 들어 있다. 조건 3종, 생성물 9개, 회차별 판정 결과.

```bash
npx tsx scripts/run-experiment.ts
```

| 조건        | 색 선언 | ok  | near | violation | uncomputable |
| ----------- | ------- | --- | ---- | --------- | ------------ |
| A 지시만    | 90      | 6   | 12   | 72        | 0            |
| B 토큰 제공 | 80      | 80  | 0    | 0         | 0            |
| C 토큰 부족 | 80      | 78  | 0    | 0         | 2            |

## 상태

개발 중이다. CLI 진입점은 아직 없다. 검사 코어의 동작은 `npm test`로 확인한다.

```bash
npm install
npm test
```

`fixtures/`의 `clean.css`와 `dirty.css`로 검사기 자체를 먼저 검증한다. 표현 방식이 달라도 값이 같으면 통과해야 하고, 심어둔 위반은 정확히 그 종류로 잡혀야 한다. 이 테스트가 통과하기 전의 검사 결과는 신뢰하지 않는다.
