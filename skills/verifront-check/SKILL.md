# verifront-check

만든 화면을 브라우저로 열어 색과 여백을 토큰·시안과 대조하고, 실패가 없어질 때까지 고친다.

눈으로 보는 확인은 이 작업에 맞지 않는다. `#3b82f5`와 `#3b82f6`, 12px과 16px은 스크린숏에서 구분되지 않는다. 코드를 다시 읽는 것도 부족하다. `padding: 16px`이 테두리 때문에 화면에서 17px이 되는 식으로, 선언한 값과 그려진 값이 다를 수 있다. verifront는 화면에 그려진 좌표와 색을 잰다.

## 준비

작업 폴더에 `verifront.config.json`이 있는지 본다. 토큰 파일과 시안 스냅숏의 위치가 들어 있다.

없으면 토큰 파일(`tokens.json` 등)과 피그마 스냅숏을 찾아 설정을 만든다. 경로는 설정 파일 기준이다.

```json
{
  "tokens": ["tokens.json", "tokens-space.json"],
  "design": { "snapshot": "design/snapshot.json", "frame": "card-list" }
}
```

토큰도 스냅숏도 없으면 이 스킬로 검사할 대상이 없다. 사용자에게 그렇게 말하고 끝낸다.

## 검사

```bash
bash <이 스킬 폴더>/scripts/check.sh <html 파일>
```

종료 코드로 결과를 판단한다.

- **0**: 실패 판정이 없다.
- **1**: 실패 판정이 있다. 출력에 판정마다 두 줄이 나온다. 첫 줄은 판정, 속성, 기대 값과 실제 값이고, 둘째 줄은 시안 노드 경로와 화면 요소의 선택자다.
- **2**: 사용법이나 설정 오류다. HTML이 아니라 설정이나 설치 문제다. HTML을 고치지 말고 오류 메시지를 사용자에게 전한다.

검사기 넷이 차례로 돈다. `tokens`는 선언된 색, `runtime`은 그려진 색, `spacing`은 여백이 간격 스케일 안에 있는지, `design`은 자리마다 값이 시안과 같은지를 본다. 앞의 셋을 통과해도 `design`에서 실패가 나오는 게 보통이다. 토큰이긴 한데 그 자리의 토큰이 아닌 값은 `design`만 잡는다.

## 고치기

`design`의 기대 값이 정답이다. 실제 값을 기대 값에 맞춘다. 기대 값에 해당하는 토큰이 있으면 숫자 대신 `var(--space-3)`처럼 토큰을 쓴다.

판정마다 고치는 방향은 `references/verdicts.md`에 있다. 처음 보는 판정이 나오면 먼저 읽는다.

여백은 좌표로 잰 값이다. 기대 16px, 실제 17px이면 선언을 16px로 바꿔도 소용없을 수 있다. 테두리 두께, `line-height`, 마진 겹침이 화면 간격에 보태지는지 확인한다.

1px 차이가 테두리 때문이면 패딩을 15px로 줄이지 않는다. `design`은 통과해도 `spacing`이 15px을 스케일 밖 값으로 잡는다. 대신 시안에서 그 요소에 선이 있는지 본다. 선이 없는 요소에 투명 테두리를 깔아 두면 내용이 1px씩 밀린다. 테두리는 시안에 선이 있는 요소에만 준다.

같은 판정이 카드마다 반복되면 원인은 대개 CSS 규칙 하나다. 자리마다 따로 고치지 말고 그 규칙을 고친다.

## 하지 말 것

- **요소를 지우거나 숨겨서 판정을 없애지 않는다.** 짝이 없어진 시안 노드는 `unmatched` 실패가 되어 다시 나온다. 결과물에서 시안의 내용이 빠지는 것은 고친 게 아니다.
- **시안의 글자를 바꾸지 않는다.** 검사기는 글자가 같은 노드와 요소부터 짝짓는다. 글자가 달라지면 짝이 어긋난다.
- **설정, 토큰, 스냅숏, 시안 명세를 고치지 않는다.** 기준을 바꾸면 검사가 의미를 잃는다. 기준이 틀렸다고 판단되면 고치지 말고 보고에 적는다.
- **verifront 자체를 고치지 않는다.** `node_modules` 안의 코드도 포함한다.

## 반복 상한

검사는 최대 3회 돌린다. 처음 검사 1회, 고친 뒤 재검사 최대 2회다.

3회째에도 실패가 남으면 멈추고 보고한다. 두 번 고쳐도 남는 실패는 검사기의 한계이거나 시안과 요구가 부딪히는 자리일 때가 많다. 거기서부터는 사람이 판단해야 한다.

## 보고

작업을 마칠 때 마지막 검사 결과를 이 형식으로 적는다.

```
검사 결과: 통과 | 실패 N개 (마지막 검사 기준)
검사 횟수: N회
고친 것: 판정과 자리, 무엇을 바꿨는지
남은 실패: 판정, 자리, 고치지 못한 이유
보고만 한 판정: 판정별 개수와 주요 사유
```

마지막 검사의 종료 코드가 0이 아니면 "완료", "통과", "시안과 일치" 같은 말을 쓰지 않는다. 실패가 남은 채 끝내는 것은 괜찮다. 남은 실패를 숨기는 것은 괜찮지 않다.
